# SF-011 下一次 Attempt 的 Admission 修订依据

**范围：仅未来新 Attempt 的 DRAFT。** SF-011 ATTEMPT-01 的 `FAILED_ADMISSION`、Public、原始采集和 SHA 保持不变，不重新评分或覆盖。其失败包括旧校验器要求控制器未写出的 `http_recovered` 字段、Service 客户端 Span 在真实暂停时仍报告 gRPC 0、以及 Image p95 比值超过旧 1.25。

独立无故障 VAL5/VAL6 使用相同 LOW-STABLE 策略、两种随机种子，两个 1,800 秒窗口均无故障且完整通过请求/Trace 质量检查。只读校准 SHA-256：`7b347645e8ce1525b7f1bfdbb6f85bbc4a3e6e2226a94656e38e891e41de19b0`。

| 无故障窗口 | Image p95 前/中/后 (ms) | 中/前 | 后/前 | Cart 中/前 | Recommendation 30 秒完成量/基线预期 |
|---|---|---:|---:|---:|---:|
| VAL5 | 1.682 / 1.440 / 1.589 | 0.856 | 0.945 | 1.106 | 1.015 |
| VAL6 | 1.628 / 2.164 / 3.123 | 1.329 | 1.918 | 0.890 | 0.963 |

旧 Image 比值 1.25 会把 VAL6 的无故障窗口判为不稳定。下一次 Attempt 建议保留每窗口 Image/Cart 样本下限，Cart 继续使用 1.25 倍上限；Image 采用 `p95 <= max(1.25 * before_p95, before_p95 + 2 ms)`，只为约 1～3 ms 的低基线增加绝对噪声带。2 ms 覆盖 VAL6 无故障后段观察到的 1.495 ms 差值并留约 0.505 ms 余量；不减少请求、Span 或模态覆盖门槛。

ServicePause 的直接公开证据改为预注册的二选一：至少 5 条带错误状态的 Frontend→Recommendation 客户端 Span；或至少 30 条真实客户端调用 Span 且故障期 Recommendation Server 完成量低于按故障前调用速率折算值的 20%。第二项已存在于早期通用竞赛可观测性合同，不依赖注入日志或私有目标字段。VAL5/VAL6 的正常完成率约 1.0，远高于 0.2。目标两个 Pod 的前后各至少 30 条 Server Trace、身份连续性、正常对照与真实注入恢复仍为独立必过条件。

HTTP 有界执行证据继续要求至少 60 条真实延迟请求、其中固定普通业务流至少 45 条、时间窗和 250 ms 参数全部匹配控制器计数；恢复使用控制器已实际写出的 `POST` 新鲜安全前检和无活动租约证据，不再要求不存在的 `http_recovered` 字段。

以上是新版本的前瞻性候选，须在新的 Run Manifest 中锁定代码、合同和校准 SHA，运行测试及新鲜安全门禁后才能注入。两轮无故障窗口的统计量不足以宣称普适噪声分布；正式评分 GT 仍需人工审核。
