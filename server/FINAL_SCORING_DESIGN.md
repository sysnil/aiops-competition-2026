# Final Stage 1 Scoring Design

Status: **simulation and internal preview only**. All seven candidate GT files remain `DRAFT_PENDING_HUMAN_REVIEW`. They are stored under `/etc/aiops-private-grader/final-gt-preview/`, readable by `aiops-grader` and inaccessible to `aiops-api`. No official Final GT was installed or approved. The Private Grader alone reads the draft and returns a preview score; official scoring returns `PENDING_GT_APPROVAL` until reviewed GT and weights are locked.

The Final answer uses v3 observable anomaly categories, not fault-injection labels. The private grader converts each draft observable event to a preview event in memory. It matches submitted events to GT one-to-one with a deterministic maximum-weight assignment; up to 32 events are supported, including SF-007's 23-event draft. Entity and interval dominate assignment, with type as a tie-breaker. A prediction and GT event can each be matched only once.

The current **preview** rubric, `final-stage1-preview-1.1`, assigns per GT event up to 40 type, 20 entity, 20 timing, and 20 evidence points. Entity-level partial credit uses the reviewed event's explicit aliases and service-level policy. Start and end use a versioned 120-second tolerance. Public evidence must pass the existing record SHA/readback verifier and correspond to the claimed entity and interval to earn evidence credit. Unmatched predictions and duplicate reports each incur a configurable 5-point deduction on the 100-point intermediate scale. The score is normalized across all GT events, clamped to `[0,100]`, then scaled to the internal 10-point task maximum. Missing GT events reduce the score; no anomalies cannot earn a perfect score. A forged Public record rejects the submission before scoring. The public breakdown omits internal GT event IDs.

The four initial 50-Agent preview submissions were scored with `final-stage1-preview-1.0`, which verified Public record authenticity but did not require entity/time relevance for its evidence points. Their stored results and grader versions were not rewritten. PK-R02 and future preview submissions use 1.1. This distinction is part of the audit and these scores are **not** official or directly comparable as final competition results.

Chart PNG bytes and SHA-256 are structurally checked by the submission schema. Chart quality, presentation, Agent execution process, optional RCA, and provider-reported model usage are **not** official point sources in this phase. Provider-reported Token usage is untrusted without a verified gateway. The organizer must approve reviewed observable-anomaly GT, the event rubric, time tolerance, matching version, task weights, judge weights, RCA bonus cap, and tie-break rule before formal release.

An isolated eight-round simulation uses the configurable `final-stage1-simulation-1.0` policy: three FT tasks contribute at most 30 points, PK automatic preview score at most 40, and average judge score at most 30. RCA bonus is zero in this simulation. This policy is explicitly not a frozen official scoring rule. The production controller refuses formal result confirmation with `FORMAL_WEIGHTS_NOT_LOCKED`; a root-only offline CLI can mutate only an isolated `--simulation` database during Stage 1.

The stored grade record contains status, grader/rubric version, matched count, false-positive and duplicate counts, per-prediction dimension scores, and score. Raw submitted answers remain immutable in the Final submission table. Repeated grading cannot overwrite a completed grade. Judge revisions before confirmation create audit entries with the previous and new score; confirmed results require a separate controlled correction procedure before formal release.
